Goldie opens with the core thesis: making one short video today takes three separate tools — one for picture, one for sound, one to edit. **What MiniMax H3 Does (0:49–2:26)**
MiniMax is a Chinese AI company based in Shanghai, founded in 2022, part of the well-funded startup group called the "AI tigers" (alongside competitors). Their video models are branded Hailuo; H3 is the newest, also known as Hailuo 3.0. MiniMax calls it a "general-purpose omnimodal generation model" — it reads text, images, video, and audio all in one shared context, where most video tools do a single job (text→clip, or animate one image). Four main capabilities: (1) text-to-video, (2) first-and-last-frame (give it a start and end image, it fills the motion between), (3) reference-to-video — the standout — and (4) video editing of an already-made clip via plain-language description.

**12 References, One Clip (2:26–3:30)**
The reference capability is what sets H3 apart. In a single generation you can pass up to nine images, three video clips, and three audio tracks — up to 12 reference files feeding one video. It reads character identity, movement style, camera work, sound, and editing rhythm, and carries all of it into the finished result. The practical payoff: the character looks identical across shots, the voice stays consistent, the style holds — the exact thing most tools fall apart on. Goldie positions this as H3's strongest differentiator.

**Native Audio + 2K Editing (3:30–4:45)**
Native audio is a major feature: every clip returns with built-in stereo sound — score, dialogue, background noise — time-synced to the cut, not silent video you dub later. Give it a voice recording and it can transfer/clone that voice onto a character while preserving performance. Resolution/length: up to 15 seconds at 2K, 24fps. Not long, but usable for social clips, ads, intros. Notably strong at rendering on-screen text — titles, subtitles, credits, brand names — which most video models garble. Can animate interface work (landing pages, menus). Prompts run up to 7,000 characters, so you can write a full shot list in one go.

**Wins, Limits, Open Weights (4:45–6:44)**
The benchmark: an independent platform called Artificial Analysis ranks models by blind human preference (people pick which clip looks better without knowing the maker). H3 took the #1 spot in **video editing**, ahead of Google and ByteDance. It also lands top-3 in text-to-video and top-3 in image-to-video — but not #1 in those. Honest caveat: it sits behind Google in text-to-video, and behind ByteDance and Google in image-to-video. So "beat the biggest models" is true where it counts most (editing) and competitive elsewhere. Critical point for the open-source ecosystem: MiniMax says it's releasing H3's weights under a community license — download, study, build on it. If that lands as described, H3 becomes the strongest open video model by a wide margin; models this capable are usually closed. That changes who gets to build with it.

**Biggest Mistake + Setup Tips (6:44–9:02)**
The mistake most people make: picking the wrong tool for the job. They see "#1 in a headline" and assume it's #1 at everything. H3 is a monster at reference work and editing; if your job is keeping a character/product/voice consistent across shots or tweaking existing clips, it's the tool. But for a single quick clip from one text line, a simpler/faster model may serve better. The mistake isn't picking a bad tool — it's picking a powerful tool for the wrong job. Five tips: (1) lean into editing, bring real footage/refs; (2) use all reference slots (9 imgs, 3 clips, 3 audio); (3) write long prompts — you have 7,000 chars, describe the whole shot; (4) check where you can run it — app/API live now, open weights rolling out; (5) always match model to job. *Full breakdown (no chapters — organized by topic threads):*

**The Problem: Agents That Forget**
Goldie diagnoses the recurring pattern: you install a new agent, day one it's amazing, then every session starts cold — it doesn't remember yesterday, needs constant babysitting, everything stops when you close the laptop, and within a week you've quietly abandoned it. His claim: that's not an agent problem, it's a missing-system problem. A chat window forgets you the instant you close it — "explaining yourself to a goldfish every morning." The fix is wrapping the agent in an operating system with three layers.

**The Three-Layer Agent OS Architecture**
Layer 1 — **The Brain**: Hermes plus the models it thinks with. Hermes is open-source, free, runs on your own machine. You can plug free models (he mentions "Omni route" for routing to free models) so running costs can be near-zero. On its own, Hermes is "still just a smart chatbot" — the magic is the layers around it.
Layer 2 — **Mission Control**: one dashboard where every job has a button — chat, voice, agent teams, and a workspace where every build lands. The point is to stop driving from a messy terminal and stop copy-pasting between Hermes/Claude/a third tool "like a maniac." Inside one OS, all agents share the same context; when a new model drops, you plug it in as a swappable part — memory, buttons, running jobs all persist.
Layer 3 — **Memory** (the one everyone skips, the one that "changes everything"): runs on Obsidian — a free folder of plain-text notes your agents read before working and write to after finishing. Holds identity, decision logs, daily logs. Agents organize it themselves — you don't maintain it by hand. Without memory, every session is a blank stranger; with it, every agent you plug in already "gets you," and it compounds — the more you work, the more the vault knows, so answers sharpen every week. A plain chat window resets each open; the Agent OS "starts full every time."

**Practical Workflows Shown**
- Video agent: type a prompt → it handles voiceover, edit, avatar → returns a finished video.
- Voice agent: speak instead of type; controls browser/computer in background ("say 'Open Obsidian' and it just opens it").
- News-watching workflow: runs around the clock, catches major model drops, drafts content, publishes straight to WordPress, returns a direct link to the live post. Also monitors competitors for content ideas.
- Agent teams on a Kanban board: drop a task (e.g., "plan the next onboarding walkthrough"), agents triage it between themselves and build while you're away. Every build lands in its own workspace so nothing gets lost.
- He no longer logs into his own websites — agents organize it all.

**The Mindset Shift (the thesis)**
"Most people collect agents. Operators build the system." Old way: chase every new model launch, get excited, abandon it, start over — "10 tools, zero systems." New way: build the three layers once, and every model after is a swappable part — a drop-down change that inherits everything (memory, mission control, running jobs). The OS is the part that doesn't change; models are never going to settle, so the OS is what compounds. "Waiting doesn't keep you safe. It just puts you behind the people who already built their system." This is the strongest argument in the video and the one most directly applicable to any professional running repetitive knowledge work.

**Implementation Tips**
(1) Don't build all three layers perfectly on day one — start with the brain (get Hermes running), add mission control, add memory last (but don't skip it — it's what makes everything click). (2) Don't worry about running costs — three models via Omni route + local engine, run a lot without paying for tokens. (3) Let agents organize the memory vault; don't do it by hand. (4) When a new model launches, resist tearing everything down — just plug it in. That one habit is "the whole difference between an operator and someone who's forever starting over."
