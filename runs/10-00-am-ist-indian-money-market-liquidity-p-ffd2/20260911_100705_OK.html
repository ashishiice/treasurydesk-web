**Working approach — Full table regex extraction (primary, most reliable, verified May 21 2026):**

The RBI MMO press release page contains **4 clean HTML tables** in a stable order. A regex-based extractor (see `references/session-2026-05-21-verified-snapshot.md` for exact row maps) is now the primary method for cron jobs because it is immune to index drift caused by empty/whitespace cells.

Quick row map reference:
- **Table 0** = Header (date, title)
- **Table 1** = Money Markets (Call Money WAR at Row 2, Overnight total at Row 1, Term segment at Rows 6-11)
- **Table 2** = RBI Operations (Today's MSF/SDF/Repo at Rows 6-10, Outstanding at Rows 14-15, Net liquidity at Row 20)
- **Table 3** = Reserve Position (Cash balances, CRR, durable liquidity surplus at Row 6)
- **Table 4** = Footer (ignore)

```python
import urllib.request, re

def extract_mmo_tables(prid: int):
    url = f"https://www.rbi.org.in/Scripts/BS_PressReleaseDisplay.aspx?prid={prid}"
    req = urllib.request.Request(url, headers={'User-Agent':'Mozilla/5.0'})
    html = urllib.request.urlopen(req, timeout=20).read().decode('utf-8','replace')
    tables = re.findall(r'<table[^>]*>(.*?)</table>', html, re.DOTALL)
    result = []
    for ti, tbl in enumerate(tables):
        rows = re.findall(r'<tr[^>]*>(.*?)</tr>', tbl, re.DOTALL)
        parsed = []
        for r in rows:
            cells = re.findall(r'<t[dth][^>]*>(.*?)</t[dth]>', r, re.DOTALL)
            texts = [re.sub(r'<[^>]+>', '', c).strip().replace('\\n',' ').replace('  ',' ') for c in cells]
            if any(texts):
                parsed.append(texts)
        if parsed:
            result.append(parsed)
    return result
```

#### Method 5: Python HTMLParser (most robust for full context)
When `sed`/`grep` tag stripping produces noisy output with embedded CSS/JS, use Python's built-in HTMLParser:
```bash
curl -sL 'https://www.rbi.org.in/scripts/BS_ViewMMO.aspx' | python3 -c "
import sys
from html.parser import HTMLParser

class TextExtractor(HTMLParser):
    def __init__(self):
        super().__init__()
        self.text = []
        self.skip = False
    def handle_starttag(self, tag, attrs):
        if tag in ['script','style']:
            self.skip = True
    def handle_endtag(self, tag):
        if tag in ['script','style']:
            self.skip = False
    def handle_data(self, data):
        if not self.skip:
            t = data.strip()
            if t:
                self.text.append(t)

parser = TextExtractor()
parser.feed(sys.stdin.read())
print(' '.join(parser.text))
"
```
This returns all RBI MMO text cleanly, including every table cell, with zero noise from CSS/JS. From the output, grep for liquidity keywords (`SDF`, `MSF`, `surplus`, `deficit`, `Net liquidity`, `outstanding`).

## Browser Harness Pitfalls

### `browser_console` return statement limitation
The browser harness's `browser_console` tool does NOT support `return` statements in JavaScript expressions. Using `return` throws:
```
Evaluation error: SyntaxError: Illegal return statement
```
**Workaround**: Use an expression that implicitly returns its value, or assign to a variable and reference it at the end:
```javascript
// ❌ FAILS — return is illegal
return document.querySelector('table').innerText;

// ✅ WORKS — implicit return via IIFE or final expression
(() => { /* code */; /* final expression becomes return value */ })()

// ✅ WORKS — use let/const and end with the variable name
let tables = document.querySelectorAll('table');
tables[0].innerText
```
**Alternative**: Use `browser_vision` with `annotate=true` when DOM text extraction via console is blocked or unreliable. Vision mode reads the rendered page directly and is immune to lazy-loading, shadow DOM, and CSP-script issues.

### CCIL T&C Dialog Blocks Data
The CCIL Swaps page loads a Terms & Conditions modal that obscures all market data tables. Data extraction will show only the dialog text until ACCEPT is clicked. Always click ACCEPT first.

**⚠️ Pitfall — Double ACCEPT (intermittent)**: In the May 12, 2026 session, the T&C dialog reappeared immediately after the first ACCEPT click, requiring a second click. However, on May 14, 2026, a **single ACCEPT was sufficient**. If console extraction still returns only dialog text after one ACCEPT, try clicking ACCEPT once more before concluding failure.

### Lazy-Loaded Table Data
CCIL tables may appear in the DOM but with empty cells until scrolled into view or until the T&C is accepted. If extraction shows mostly blank cells after accepting T&C, scroll the table into view or use `browser_vision` with a targeted question.

## Common Pitfalls
1. **Don't hardcode CCIL sub-page URLs** — bot detection blocks them. Always navigate from home.
2. **CCIL data timestamp** — Check "As on date" on page (often previous day's close)
3. **RBI MMO publication time** — Usually 10:00-11:00 AM IST for previous day's data
4. **OIS vs FRA** — Don't confuse OIS (MIBOR-based swaps) with Forward Rate Agreements
5. **RBI PDFs have CAPTCHA** — Always use the HTML press release page, never the PDF link
6. **FBIL data lag** — FBIL often shows data 1-2 days behind. However, for MIBOR OIS, FBIL may be more current than CCIL when CCIL shows no current-day trades.
7. **CCIL "0.00" values** — When markets are closed (weekends/holidays), CCIL shows 0.00 for Open/High/Low/LTR/Volume/WAR columns. Check the "Prev. Day WAR" column for the last meaningful rate.
8. **Weekend/Holiday data lag** — RBI Money Market Operations published on day T actually reflects data from T-1 (previous business day). After a 2-day weekend, expect to see Friday's data on Tuesday morning (T+3 lag). Factor this into liquidity assessments.
9. **Two tables on CCIL Swaps page** — The top table is "MIBOR OIS" (use this); the bottom table is "MODIFIED MIFOR" (ignore). Confusing them leads to wrong 1Y/5Y rates (e.g., 6.67% vs 7.30% for 5Y on May 4, 2026).
10. **PRID verification trap** (June 9, 2026 lesson) — RBI serves ANY valid prid with the page template, including years-old press releases. A successful HTTP 200 + the press release template does NOT mean you found the right MMO. **Always verify the H1/H2 contains "Money Market Operations as on [target date]" before trusting the data.** Brute-forcing prids across wide ranges (e.g. guessing ±100 IDs) can return valid 200 responses for completely unrelated historical press releases. Use the listing page extraction method (see `references/vrr-result-listing-page-discovery.md`) instead.
11. **Trend baseline ≠ previous calendar day** — When computing "vs prev day" deltas, use the last FULL business day's MMO, not the immediately prior calendar day's MMO. Saturday/holiday MMOs show zero market volumes (only SDF/MSF active) and Saturday afternoon MMOs are partial-day. Skipping these gives cleaner trend signals.
12. **VRR vs VRRR direction** — VRR (Variable Rate Repo) is INJECTION (RBI lends to banks); VRRR (Variable Rate Reverse Repo) is ABSORPTION (banks park with RBI). The daily MMO's "(a) Repo Operation" line aggregates VRR; "(b) Reverse Repo Operation" aggregates VRRR. If a press release announces VRR, that means RBI is adding liquidity, not tightening — counter-intuitive from the "repo" name.
13. **Don't fabricate missing rates** — If MIBOR 1M, OIS 1Y/5Y, or CBLO rates are not retrievable from public sources, state the gap explicitly with a note like "not available from public sources at this timestamp". This is preferable to using stale broker data or leaving cells blank without explanation.

- For numeric data, always include a markdown table AND follow it with bullet-point interpretation.
